# Agent and LLM Boundary

## Core design

The Agent node is the first runtime boundary that uses the State contract:
`AgentState.messages` plus RuntimeContext model input produces one `AIMessage`.
The node reads messages and returns a partial update; it never mutates the
history in place.

## Model and prompt lifetime

The chat model belongs to RuntimeContext, not State. Bootstrap constructs it
through the small provider factory after configuration and credential
resolution. The system prompt is added temporarily to the model input and is
not persisted into `AgentState.messages`, so repeated graph steps do not
accumulate duplicate system messages.

## Provider boundary

The old dict-based LLM client protocol was removed. The supported provider now
uses LangChain's `ChatDeepSeek`, preserving LangChain message objects for later
tool-call work. This round intentionally does not bind tools; the Agent path
only returns a normal `AIMessage` and the existing `route=finalize` remains a
scaffold routing choice.

## Current reality

Bootstrap can construct a configured DeepSeek model, while tests inject a fake
model and never call the network. Credential values are read only inside the
LLM boundary when model construction occurs and are not placed in State or
logs. Tool, memory, approval, and real reasoning behavior remain unimplemented.

## Open questions

- How should model tool calls map to the next State/Capability boundary?
- Which model configuration belongs in RuntimeContext once streaming is added?
- When should the Agent route to a tool versus finalize?
